# AMOS highlighting preview 0.3.0

This preview provides Professional-based lexical highlighting for plain-text
AMOS listings, with optional AMOS 3D, standalone AMAL and standalone Interface
modes. It is a published preview, not a claim of complete AMOS support.
The npm and editor packages use 0.3.0. The Rust parser remains 0.1.0.

## What is included

- 728 documentary BASIC entries across 44 partial/full manual sections, including
  file/device I/O, sound, resources, memory/call/register and Copper forms.
- The opt-in `amos-3d` profile with its separate 59-record extension inventory.
- Standalone `amal` with 36 records, significant capitals and register contexts.
- Standalone `amos-interface` with 69 records/68 codes, lowercase padding,
  opaque quotes and a neutral builtin scope for SW's two documented roles.
- Selected decimal/scientific forms, line-head labels followed by statements,
  numeric line identifiers, both BASIC quoted-string forms, and corrected
  numbered/inline Rem handling.

Counts name inventory entries, not unique-instruction totals or a coverage
percentage. BASIC strings remain opaque; AMAL and Interface require explicitly
selected modes. Only plain-text `.amos.txt` files select AMOS automatically.

## Preview channels and installation

The npm channel is `next`, preserving `latest` at 0.1.0.
Use `npm install @lang198x/amos@next` or pin
`@lang198x/amos@0.3.0`. The additive registrations are `@lang198x/amos/amos-3d`,
`@lang198x/amos/amal` and `@lang198x/amos/interface`; the default import is AMOS.
Do not run a folder-based publish in place of the verified release archive.

The downloadable VSIX is `lang198x-lang198x-amos-0.3.0.vsix`. Install it through
**Extensions: Install from VSIX**. It retains `lang198x.lang198x-amos` and carries
both the Preview label and the prerelease-channel property. A Preview label
alone does not select the prerelease channel. No Public gallery flag is included.
The public Marketplace preview is editor-only 0.3.1; it adds public-listing
metadata to these same four grammars. See the [editor release](0.3.1.md).

VS Code requires numeric extension versions and recommends odd minor versions
for prereleases; see [Microsoft's publishing guide](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#pre-release-extensions).
The extension's `preview` field supplies the separate [Preview label](https://code.visualstudio.com/api/references/extension-manifest).
The retained numeric npm version follows the earlier package convention;
[npm's `next` dist-tag](https://docs.npmjs.com/adding-dist-tags-to-packages/) and
GitHub's prerelease flag identify its preview status. `publishConfig.tag` also
defaults the package to `next`.

## Evidence and limits

The readiness baseline includes 35 package checks, 264 integrations per existing
consumer, pinned original-tokenizer evidence, two independent programs and a
numeric regression fixture. All four modes have been visually reviewed in native
VS Code dark/light themes. Release preparation adds direct archive checks for
version, Preview label, prerelease channel, unchanged source assets and isolated
installation. All 38 preparation package checks and 264 integrations per
consumer pass. Extracted declarations and an isolated VSIX installation pass.
The release evidence record binds the exact source commit, CI,
archive hashes and observed results.

Creator, Easy, other Professional revisions and extension versions remain
unqualified. Highlighting does not validate arguments, expression results,
resource availability or native import/execution. Arbitrary spacing, uncommon
literal/editor forms, extended identifiers and other encodings are outside this
preview's qualified surface. No native `.AMOS` decoder, compiler or language
server is included; the Rust parser still handles only its opening-program subset.

See [coverage](../coverage.md), [readiness](../highlighting-readiness.md) and
[verification](../verification.md). Existing 0.1.x/0.2.0 releases retain their
original assets. The [publication record](0.3.0-publication.json) records registry
readback and trusted-publishing verification.
