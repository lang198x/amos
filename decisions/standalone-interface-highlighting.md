# Add a standalone Interface lexical mode

Approved on 21 October 2026 after the definition inventory and explicit choice
of the standalone opt-in approach.

Follow the existing AMAL adapter shape: a canonical self-contained TextMate
asset, additive npm `interface` subpath and explicitly selected `amos-interface`
editor mode. No automatic association or injection into BASIC strings. Exact
editor copies use the existing sync/build checks. No dependency, parser, compiler,
runtime, version bump or publication is commissioned; Marketplace stays private.

Professional §§9.1–9.4 supply the documentary profile: 69 code/role records,
68 distinct codes. Respect significant capital pairs and lowercase padding.
Follow AR/AS's function definitions; give SW a neutral builtin scope in both
roles. Recognise documented quoted strings, integer/binary/hex literals,
parameters P1–P9, symbolic operators, NEg and separators/brackets. Keep Min/Max
capitalisation and the Call/CAll discrepancy unresolved rather than inventing
aliases. Do not split adjacent digits into inferred stack operands.

This is lexical highlighting, not postfix/argument evaluation, validation of
terminators (including BU's final-bracket exception), custom-name resolution,
callback/zone-context checking, HyperText injection or native qualification.
Unknown capital groups remain neutral. Lowercase text is ignored padding rather
than an imported BASIC Rem-comment grammar. Strings recover at line boundaries.
