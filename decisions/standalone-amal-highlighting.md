# Add a standalone AMAL lexical mode

Approved after review of the standalone AMAL plan on 20 October 2026.

Use a self-contained canonical TextMate grammar, an additive npm `amal` subpath,
and an explicit AMAL mode in the existing declarative editor extension. Reuse
existing consumers and package verification. No new dependency, lexer/AST,
compiler, runtime, version bump or publication is commissioned.

Professional §7.6 supplies the documentary profile. Respect significant capitals,
lowercase padding, one-capital labels and separate register/expression/instruction
contexts. Test all 36 existing inventory records and preserve source uncertainty.
The first lexical mode does not resolve every separatorless ambiguous A/X role,
validate expressions, resolve labels or qualify runtime versions. Unsupported
forms remain neutral rather than becoming invented aliases or diagnostics.

BASIC strings remain opaque in both AMOS modes, and automatic file associations
stay unchanged. This extends the manual-led-highlighting canonical-asset rule to
a separate embedded language; it does not introduce another AMOS semantic parser.
Marketplace remains private and published 0.2.0 assets stay unchanged.
