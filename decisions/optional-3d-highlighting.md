# Offer explicit AMOS and AMOS + AMOS 3D modes

Approved 20 October 2026. Keep the existing AMOS registration, file association
and grammar behaviour. Add an opt-in AMOS + AMOS 3D mode for VS Code, a separate
`amos-3d` registration/subpath for npm consumers, and self-contained TextMate JSON.

The BASIC grammar remains canonical. A small canonical 3D fragment owns extension
rules. Explicit composition produces the combined grammar and the editor gets
an exact copy. This narrowly extends the manual-led-highlighting decision's
single canonical grammar arrangement: no second hand-maintained BASIC grammar
and no general grammar-generation or extension-configuration framework.

Start with the 59 manual records, using pinned source findings for spelling and
command/function roles. Movement strings remain opaque. Later publisher-source
tokens need separate inventory work. Profiles select lexical vocabulary; they
do not qualify AMOS editions, extension releases, parser acceptance or execution.

No new dependencies, extension host code, parser behaviour, release versions or
publication. Marketplace remains private. Test profile isolation, all inventory
records, mixed listings, longest forms, case/spacing, identifiers, comments and
strings, plus existing BASIC regressions in both themes and existing consumers.
