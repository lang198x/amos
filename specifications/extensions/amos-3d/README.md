# AMOS 3D extension scope

AMOS 3D belongs in the language roadmap as an optional extension. It is not AMAL
and does not become part of core AMOS because a highlighter recognises its words.
The held guide and quick card are bound by SHA-256 in `source.json`; its evidence
records cite exact extract lines and printed pages. The 1991 date follows the
reference catalogue, whose bibliographic details have not all been title-checked.

The guide describes installation of a command extension (p. 11) and says AMOS 1.3
or later is required (p. 5). That is a documentary minimum-version claim, not proof
that every Creator or Professional release loads the extension. No release or
installation is qualified here. Nothing is installed or downloaded by this work.

The next bounded 3D milestone should inventory the programming chapter and quick
card by command family: object loading/lifecycle, positioning/attitude, coordinate
conversion, visibility/collisions/zones, point/surface animation and backgrounds.
Keep `Td` forms and extension provenance separate from the Professional core
checklist. Crosscheck grouped X/Y/Z and A/B/C variants and read/query forms.
The movement and rotation strings also need their own documentary treatment.

Resolve discrepancies before implementation. For example, the guide's prose says
`Td ANGLE REL` (p. 78), but its signature and quick card print `Td ANGEL REL`.
These are not two established aliases. Check the original extension artefact or
another independent primary source before choosing accepted spellings. The quick
card's two-column layout and omitted argument markers require guide crosschecks.

After that inventory, agree how optional highlighting/profile selection should
work, preserving existing package exports and consumers. Native availability,
object formats, runtime behaviour and tokenised persistence need separate evidence.
No Td highlighting, parser, codec, compiler or runtime is implemented by this scope
record. Native formats remain outside the language frontend's ownership.
